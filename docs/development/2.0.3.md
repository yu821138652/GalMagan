# 2.0.3 微信空节点读取排查

版本号为 `2.0.3`，版本代码 `41`。

用户实测仍显示“总节点 1”。这表示本次遍历只取得根节点，没有取得可遍历的子节点；仅凭这一项无法区分窗口选择错误、无障碍服务配置、系统行为或微信未提供内容，也不能据此确定是截屏限制所致。

后续用户截图实际显示“总节点 5、可见节点 1、根子节点 4”，输入栏、消息列表和正文均为 0。这说明还存在只有少量外层节点的情况，不能一概按只有空根处理。新版诊断补充前八个节点的类型、子节点数、可见状态、文字长度与边界，不记录正文。服务悬浮窗由普通应用悬浮窗改为 `TYPE_ACCESSIBILITY_OVERLAY`，让底层窗口在面板展开时仍可参与无障碍检查；这属于依据平台窗口语义的兼容调整，不能单凭代码判定已经解决这台手机的问题。

本轮代码检查发现：窗口候选原先按窗口 ID 去重，可能保留先取得的空根而丢弃同一窗口后取得的完整根；指定聊天环境时也可能从候选中挑到后台应用。修订后的选择逻辑保留同一前台窗口的多份快照，空根只由同窗口、同应用的非空根替换，指定环境不能覆盖前台应用判断。相应回归用例覆盖同窗口快照替换、后台旧窗口、其他应用、未知窗口 ID 和空根。

手动分析和预加载不再反复清理全局节点缓存，保留刷新按钮的主动清理。清缓存与当前设备空树之间的因果关系尚未证实，这项调整不能单独作为根因结论。手动读取时暂停自动采集对界面的覆盖，停止或刷新会使旧重试失效。

服务连接时重新设置动态标志及窗口、文本事件订阅。窗口内容和截屏能力来自 XML 元数据，运行时代码不能强行授予。事件文字可能来自标题、列表预览或输入草稿，因此仅保留数量、窗口 ID 和时间用于诊断，不作为消息发送给模型或写入历史。微信自动截图继续关闭，手动截图入口保留。
