# 2.0.2 微信读取修复说明

版本号为 `2.0.2`，版本代码 `40`。本版不替换 `v1.6.4` 回退归档，也不发布 GitHub Release。

## 问题定位

微信报错中的“总节点 1、可见节点 0、输入栏 0、正文 0”说明适配器拿到的是只有根节点的 `AccessibilityNodeInfo`，不是已经进入聊天但没有识别到输入栏。旧代码对这个对象调用一次 `refresh()` 后仍继续遍历旧对象，清缓存后也没有重新从活动窗口获取新根，因此后续识别必然失败。

## 修复内容

- `chatRoot()`重新收集 `rootInActiveWindow` 和同一前台应用的应用窗口根节点；空根刷新后重新取根，清缓存后再次重新取根。
- 手动分析遇到微信空树时自动重试最多三轮，自动读取路径最多进行四轮恢复尝试。
- 微信适配器在普通树遍历没有子节点或没有 `bkl` 消息节点时，通过 `findAccessibilityNodeInfosByViewId("com.tencent.mm:id/bkl")` 查询消息容器。查询结果用屏幕坐标和消息资源 ID 校验，不把任意文本当成聊天内容。
- 保留微信自动截图关闭策略，不通过截图绕过微信的截屏限制。

## 验证

本地 `:app:testDebugUnitTest :app:assembleDebug` 通过，节点测试覆盖只有 provider 根节点但能查询到微信消息节点的情况。没有连接荣耀 Magic7，无法确认当前微信版本是否仍提供 `bkl` 查询结果；若新版微信连资源查询也返回空，应用会继续显示窗口和节点诊断，此时属于微信无障碍接口未提供正文，不是 OCR 或模型问题。
