## 配置迁移

使用“通用模型接口”中原有聊天接口地址、密钥及模型配置。新安装默认模型 ID 为 `gpt-6-luna`，已有模型值保留，可手动修改。不预设中转站域名，也不保证其他服务商支持此 ID。

默认选择“通用模型（无需 Jev）”。此模式没有 Jev 网络调用。可选 Jev 辅助模式最多读取风险参考；缺少密钥、额度不足或请求失败会继续通用流程，不参与候选排序。通用接口必须使用自己的密钥，不再借用 Jev 凭据。

“测试连接”仅验证文本聊天。“测试完整分析”用虚构朋友聚餐对话运行三个阶段，成功只表示完整协议可用，不能证明判断准确。

## 请求职责

1. 本地整理已选联系人的历史、当前可见消息、背景与本次补充。跨环境历史保留来源，未知原始时间不填采集时间；跨软件数组顺序不视为时间顺序。
2. 模型分析话题、未解决问题、双方明确事实、可能情绪与诉求、缺失背景、风险依据，随后制定回复策略。本阶段不注入说话风格正文。
3. 模型接收同一真实上下文、本轮分析和策略、方向及历轮补充、适用风格，生成三条不同候选。
4. 同一模型以候选检查职责重新读取上下文、分析及草稿，检查并修正说话人、自问自答、事实与承诺、最新消息、方向和边界，最终按适合策略的顺序显示三条候选。

通常三个顺序请求。某阶段结构无效或检查不通过时，允许该阶段修正一次，仍无效就明确报错，不填充虚构兜底候选，也不显示未检查的草稿。模型自检标志仅用于控制流程，不代表候选必然正确。

0—9 风险定义延续已有层级，不能由风险高低反推心理。无置信度、概率和排序百分比展示。方向不覆盖事实，风格不覆盖边界、风险或事实。

## 本次补充

补充与真实消息分开传输，记录全部有效轮次，并将引用候选的补充与对应的上一轮模型输出配对。模型输出只用于理解用户所指，不能成为事实证据。事实纠正修正判断依据，表达偏好调整策略和措辞；后续候选仍重新检查。

调整只在服务内存中保留，不写入历史、知识库或风格。新消息、切换联系人或环境时清除旧调整；“清除本次调整”同时移除前轮输出，再从原始聊天重新分析。显式重新分析会重新采集当前聊天。

悬浮窗输入框仅在编辑时取得键盘焦点，提交、折叠和填入前释放焦点。候选填入始终查找原聊天应用的输入栏，不查找悬浮窗编辑框，不点击发送。

## 验证方法

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

离线测试使用脚本响应验证依赖关系；本地 HTTP 模拟接口检查实际发送的是 chat-completions 而非 Jev 专用协议，并模拟 Jev HTTP 402 后继续完整流程。另保留节点读取、历史去重、编辑与批量删除回归测试。

中文案例保存在 `app/src/test/resources/analysis-cases-zh.json`。九组覆盖正常聊天、冲突、玩笑、讽刺、我方最后发送、缺背景、明确拒绝、跨环境历史和连续纠正；每例附人工质量观察点，不预填“标准风险分”或准确率。

可选真实模型评估使用环境变量 `GALMAGAN_EVAL_BASE_URL`、`GALMAGAN_EVAL_KEY`，以及可选的 `GALMAGAN_EVAL_MODEL`（默认 `gpt-6-luna`）。在本机安全设置后执行：

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests '*LiveModelEvaluationTest' --rerun-tasks
```

结果写到被 Git 忽略的 `app/build/reports/general-model/live-evaluation.json`。凭据不写入报告；报告包含案例分析与候选，应逐条人工审阅观察点，不把结构成功当作质量通过。没有环境变量时此项跳过，不读取手机或其他目录中的密钥。
