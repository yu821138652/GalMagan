个人维护的 Android 聊天辅助项目，基于上游项目二次开发，主要用于荣耀 Magic 系列手机上的微信和小红书测试。

## 功能

- 通过 Android 无障碍服务读取当前可见聊天内容。
- 悬浮窗显示识别结果、分析结果和候选回复。
- 默认由通用模型顺序完成情境与风险分析、回复策略、候选生成和候选评审，不需要 Jev 密钥。
- 分析界面支持默认、安抚与化解冲突、自然延续话题、增进好感四种聊天方向，以及本次分析内的多轮补充。
- 分析中可停止；悬浮窗设置左侧提供刷新按钮。分析结果不再展开列举事实，缺失背景默认折叠。
- 支持联系人选择，不依赖会话标题自动识别联系人。
- 联系人选择列表提供“默认（不使用联系人历史）”模式，适合临时分析未加入知识库的聊天对象。
- 为每个联系人按聊天环境分别保存本地历史聊天记录。
- 预加载流程为选择联系人、选择聊天环境、开始加载；过程中显示进度并支持停止保存。
- 后续自动更新按联系人和聊天环境分别去重。
- 预加载从最新位置接续已有历史，再按相邻页面的重叠向前补全；自动更新只记录最新位置，保持环境内顺序。
- 历史详情支持长按编辑正文、修正发送方，以及多选删除；删改后保留阅读位置。
- 候选回复只填入输入框，不自动发送。
- 微信自动截图关闭，手动截图识别入口保留；无障碍读取依赖微信提供消息节点，若仅返回空根节点则无法获取正文。

## 隐私与安全

- API 密钥保存在 App 私有设置中，不提交到 Git。
- 联系人资料和聊天历史保存在手机 App 私有目录，不会写入本仓库。
- 项目不读取聊天应用数据库，不注入或修改微信/小红书，不自动点击发送。
- 模型请求是否发送聊天内容取决于用户配置的接口。

## 构建

需要 JDK 17、Android SDK 35 和可用的 Gradle Wrapper 环境：

```powershell
.\gradlew.bat :app:assembleDebug
```

运行单元测试：

```powershell
.\gradlew.bat :app:testDebugUnitTest
```

生成的 APK 位于：

`app/build/outputs/apk/debug/app-debug.apk`

本项目不在 Git 中提交构建缓存或 APK。测试时请在手机上授予无障碍服务、悬浮窗和必要的后台运行权限。

## 使用说明

1. 安装 Debug APK 并打开应用。
2. 在设置中选择“通用模型（无需 Jev）”，填写通用模型接口地址、密钥和模型 ID；本次目标模型 ID 为 `gpt-6-luna`。使用中转站提供的 OpenAI 兼容聊天接口，不推定其他服务商支持该 ID。
3. 开启无障碍服务和悬浮窗权限。
4. 在知识库中添加联系人，然后在聊天界面从联系人列表选择对应对象。
5. 临时分析未添加的对象时，选择“默认（不使用联系人历史）”；此模式不会读取或保存联系人历史。
6. 首次使用联系人模式时，在悬浮球菜单点击“预加载历史记录”，选择联系人和聊天环境，进入对应聊天后开始加载；完成后再开启自动更新。
7. 微信等应用如果限制截图，不要反复触发截图；优先使用无障碍识别路径。
8. 先“测试连接”，再“测试完整分析”；前者成功只证明接口能返回文本，后者才会运行分析、生成与评审三个阶段。
9. 在悬浮分析界面选择聊天方向。分析后可填写“补充说明／调整方向”，连续补充事实或表达偏好；清除按钮仅清除本次调整。新消息、联系人或聊天环境变化会使旧调整失效。

## 2.0.0 开发说明

情境分析先区分明确事实、可能解释和缺失背景，再给出 0—9 级风险、依据与回复目标。随后根据这份分析、用户方向、补充和适用风格生成三条候选，最后逐条检查说话人、自问自答、事实与承诺、最新话题、用户方向和边界，修正后再显示。

通用模式不会请求 Jev。可选的“通用模型 + Jev 辅助”只读取风险参考；未配置、无余额或失败时仍继续通用流程。面向用户不再展示置信度或候选排序百分比。

更新保留原应用标识、配置文件及历史结构。已保存的聊天接口地址和模型不被覆盖；缺少通用接口密钥时需自行填写，不再把 Jev 密钥自动发给聊天服务。新安装默认模型为 `gpt-6-luna`。

本轮微信读取排查见 [2.0.3 测试说明](docs/development/2.0.3.md)；前轮修复见 [2.0.2 测试说明](docs/development/2.0.2.md)；2.0.1 的悬浮窗和历史修复见 [2.0.1 测试说明](docs/development/2.0.1.md)；通用模型开发、验证和回退方法见 [2.0.0 测试说明](docs/development/2.0.0.md)。

## 1.6.4 归档内容

- 点击分析后重新读取前台聊天并显示状态；修复历史面板阻挡读取和模型请求状态覆盖。
- 微信保留 1.6.0 消息节点规则，兼容未暴露输入栏但有消息正文的布局；空节点时刷新缓存并检查同一前台应用的其他窗口，显示节点与窗口诊断。
- 微信自动截图保持关闭，截图前再次核对前台应用；悬浮球中的手动“截屏识别一次”入口保留。
- 设置中的历史详情可编辑消息和发送方、多选或全选删除，并保留阅读位置。
- 小红书预加载、自动记录、分析优先读取无障碍消息节点，正文为空时才回退到 OCR。
- 联系人历史仍按聊天环境分别保存和去重，但分析时合并该联系人的所有聊天环境历史。
- 分析实际注入模型的消息和悬浮窗上下文查看均标注来源环境，例如“微信”“小红书”。

## 已知问题

- 微信偶尔仍无法读取消息，实测曾出现“总节点 1，其余 0”的空节点树。当前保留节点刷新和窗口诊断，问题尚未解决；自动截图继续关闭。
- 小红书已由维护者真机确认可用；若应用未提供正文节点，会回退到 OCR，识别结果可能存在文字或发送方错误。
- 本地 29 项单元测试通过，构建成功；历史窗口交互等界面行为仍以真机效果为准。
